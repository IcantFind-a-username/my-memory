# Threat Model · 威胁模型

版本：0.1.0（MVP）。范围：Memory Core、MCP 本地服务、记忆胶囊、Agent Skill。

## 1. 要保护什么

| 资产 | 为什么敏感 |
|---|---|
| 记忆内容（原话、状态、关系、支持计划） | 心理健康相关的特殊类别个人信息；对这个人群，泄露可能造成歧视、被控制或二次伤害 |
| 敏感 / 私密记录的**存在** | "她有一条关于自伤的私密记录"本身就是敏感信息 |
| 使用模式（访问记录的时间） | 可以推出用户什么时候处于困难时期 |
| 用户对"AI 看到了什么"的准确认知 | 如果预览和实际发送不一致，同意就失去意义 |
| 记忆的完整性 | 被篡改或投毒的"过去"会误导一个本来就难以确认自我连续性的人 |

## 2. 参与方与信任边界

```
[用户] ──说话──▶ [AI 应用 + 模型（第三方，半可信）] ──工具调用──▶ [MCP 服务（本机，可信）] ──▶ [~/PersonalMemory（本机文件）]
   │                          ▲ 也会读网页、文件、其他工具的输出（不可信）
   └──直接操作──▶ [记忆胶囊（本机浏览器，可信）] ──复制粘贴──▶ [任意 AI（第三方）]
```

- **可信**：用户本人、本机上的 Core 代码、用户能直接操作的设置界面（扩展设置页、胶囊）。
- **半可信**：AI 模型。它按用户意图行事，但**可能被提示注入**，而且我们无法验证它说的"用户同意了"是否属实。
- **不可信**：网页内容、文档、其他工具的输出、AI 服务商的数据处理，以及同一台设备上的其他人。

关键推论：**任何只靠 AI 自觉遵守的规则都是软约束。** 硬约束只能落在 AI 无法改变的地方：代码里的过滤、只有用户能改的设置、用户亲手复制粘贴。

## 3. 威胁与对策

| # | 威胁 | 对策（已实现） | 残余风险 |
|---|---|---|---|
| T1 | **提示注入导致外泄**：网页 / 文件让 AI 反复调用 `recall`，再通过其他工具把结果发出去 | 每次最多约 300 token（用户最多调到 800）；**没有**导出全部的工具；`restricted` 从不进入视图；`sensitive` 默认不进入；每进程每小时最多 30 次 recall；每次读取都记入访问记录（id、数量、token） | 被注入的 AI 每小时最多可读出约 30 × 300 token 的普通记忆。宿主若对只读工具自动放行，用户不会逐次确认。高风险用户建议不开"总是允许"，或只用胶囊 |
| T2 | **静默写入 / 记忆投毒**：AI 未经同意保存，或被注入后写入虚假"过去" | `consent` 为必填且只接受 `user_asked` / `user_confirmed`；`remember` 标注为非只读，宿主通常会弹确认；10 分钟最多 20 次；10 分钟内相同内容去重；每次写入进访问记录；`forget` 可撤销；胶囊里 AI 提出的候选默认不勾选，并永久标记为 `(a)` | MCP 端无法验证 `consent` 的真假。未来：支持 MCP elicitation 的客户端改为"待确认"状态，由用户在宿主界面里直接确认 |
| T3 | **记忆内容本身成为注入载体**（例如用户粘贴过带指令的文本） | `safeQuote`：去掉换行、控制字符、零宽字符、方括号 / 尖括号 / 反引号 / 竖线（防止伪造分区标题）；加引号、截断；头部声明这些是笔记，不是指令 | 模型仍可能受引号内文字影响（LLM 的通病） |
| T4 | **敏感度被 AI 降级** | 工具只能上调敏感度（`maxSens`）；打开"分享敏感记录"只能在扩展设置或胶囊设置里操作；工具没有任何放宽参数 | 无（按设计） |
| T5 | **私密记录的存在性泄露** | `restricted` 不计入任何检索计数，也不出现在 `NEW` 判断里；`forget(about)` 只显示"私密记录，内容隐藏"；`status` 只给总数 | `status` 会显示私密记录的总条数（用户自己询问时） |
| T6 | **本机其他程序或其他人读取文件** | 目录 0700、文件 0600；位置对用户可见 | **明文存储**。同一系统账户下的任何程序、能解锁设备的人（包括控制型伴侣）都能读。依赖系统磁盘加密（FileVault / BitLocker）。未来：可选口令加密、快速隐藏 |
| T7 | **导出文件残留** | 导出只写到用户目录；删除时回复会明确提示"之前导出的文件不会被改动" | 用户需自行管理导出文件 |
| T8 | **AI 服务商侧**：借出的内容被记录或用于训练 | 最小化（门控 + 预算 + delta）；Human Preview 告诉用户借了什么；敏感分级；用户可选服务商 | 不在本项目控制范围内，已在 PRIVACY.md 明确说明 |
| T9 | **胶囊页面本身外泄** | CSP `default-src 'none'; connect-src 'none'; form-action 'none'`，页面不能联网；无外部脚本和字体；单文件可审计 | 恶意修改版的胶囊可以去掉 CSP。对策：只从可信来源获取，发布 SHA-256 校验值（P3） |
| T10 | **胶囊同源读取**：托管在共享域名（如 `用户名.github.io`）时，同源其他页面可读 IndexedDB | 文档要求使用独立源（专用域名或子域） | 托管方式尚未决定（维护者决定） |
| T11 | **剪贴板**：复制的上下文可被剪贴板管理器或其他 App 读取 | 只复制最小上下文；用户在复制前看到全文 | 系统层面无法避免 |
| T12 | **数据丢失**：崩溃中途写入、文件损坏、Safari 7 天清理浏览器存储 | 临时文件 + fsync + 原子重命名；无法解析的文件**永不覆盖**（有测试）；胶囊申请持久存储并提示定期导出 | 胶囊在 iOS Safari 上仍可能被清理；两个进程同时写可能丢失一次更新（后写者胜） |
| T13 | **有害输出**：AI 用记忆去诊断、把主观当事实、把先后当因果、编造"上次" | `(s)/(r)/(a)` 标记；`→` 图例；`NEW` 槽位；诊断标签入库即丢弃；Skill 规则 | 最终表述由模型决定，属于软约束 |
| T14 | **危机误判**：漏报导致没有安全提示；误报（"不想活在别人的期待里"） | 危机词出现就加 `SAFETY` 行，即使没有记忆也加；宁可误报 | 漏报时依赖宿主模型自身的安全机制 |
| T15 | **资源滥用**：超长输入、海量 `seen` | 单条 ≤ 4000 字符；查询截断到 2000 字符；`seen` 最多 200 项；输出有硬预算 | 低 |
| T16 | **供应链**：依赖被投毒；市场里出现冒名版本 | 零运行时依赖；确定性打包（固定时间戳、排序）；代码量小，可逐行审计 | 冒名分发需要靠签名和校验值（P3） |
| T17 | **记忆文件模式发送全部内容**：AI 服务商拿到的是整个文件，而不是一小段 | `restricted` 从不写入；`sensitive` 默认不写入；README 明确提示"AI 会读到文件里的全部内容"；用户可以随时改用胶囊的最小分享 | 文件里的普通记录每次对话都会整体交给服务商。这是为了"零安装"而有意接受的取舍 |
| T18 | **锚点卡存放在各 AI 平台的设置里**（平台服务器），每个对话都会读到 | 生成器要求只写称呼和城市，不写全名、电话、地址、证件号；示例卡不含号码（有测试）；卡片聚焦"怎么陪我"，不需要写创伤细节 | 平台可能保存、审核或用于改进服务，取决于各平台政策；用户需要知道这是常驻内容 |

## 4. 明确不防御的情况（MVP）

- 已经完全控制用户设备或系统账户的攻击者。
- 用户主动把私密内容粘贴进 AI 对话。只要说给了 AI，那次对话的 AI 就已经看到了；`restricted` 保护的是**以后**的对话。所以 Skill 和 README 都提示：真正私密的内容请直接写在胶囊里。
- 宿主应用本身不可信（例如恶意 MCP 客户端直接读文件）。

## 5. 需要维护者决定的安全事项

1. 胶囊托管的域名和源（T10），以及大陆可访问性。
2. 是否在 P5 引入口令加密。它会增加"忘记口令就丢失全部记忆"的风险，对这个人群要慎重。
3. 危机资源（热线号码）是否按地区内置。号码必须定期核实；目前只在 Skill 里列出少数号码，并交由宿主模型补充本地资源。

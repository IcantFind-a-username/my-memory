# Adversarial Self-Review · 对抗性自检

目的：假设这个 MVP 会伤害用户、会泄露、会说谎、会装不上，然后去找证据。每一条都注明严重程度、是否已修复、证据在哪里。

## 0. 结论先行

- **核心链路成立**：Day 1 保存，Day 20 用约 94 token（保守估计）给出忠实的上下文；无关问题 0 token；同一对话不重发（`test/chain.test.js`、`npm run demo`）。
- **硬边界成立**：`restricted` 在所有 AI 路径上都不可见；AI 不能降低敏感度，也不能打开敏感分享；没有 dump（`test/privacy.test.js`）。
- **还没有证明的**：检索质量在真实用户、真实说法上的表现。现有 40 项测试证明的是*行为*，不是*质量*，不能当作召回率 / 准确率的证据。
- **"几分钟能装好吗"**：Claude Desktop 用户可以（发布后双击安装）；电脑浏览器用户可以（打开一个 HTML）。**以手机为主的大陆用户目前还不行**：胶囊需要一个可访问的托管地址，这是分发上的第一阻碍，需要维护者决定。

|---|---|---|---|---|

| F9 | 低 | 解析器升级后，旧笔记的结构化结果不会更新 | 浏览器里旧数据仍显示"麻木" | 每条笔记现在保存 `parser` 版本和 AI 提示 `hints`，以后可以从原话重新结构化；迁移本身尚未实现（O6） |

## 2. 对抗性探测（脚本化）

原计划由一个未参与实现的审查代理独立攻击，但它三次都中途卡死，**没有产出**。下面的探测是实现者本人用脚本逐条攻击威胁模型中的不变量，所以**不能算独立审查**。上线前仍需要一次真正独立的人工审查。

**守住的**（探测脚本：`restricted` 笔记 × 8 种问法 × 8 种 focus × 开 / 关敏感分享；预算 60 到 5000 以及非法值；危机、超长锚点、超长留言）：
- `restricted` 的内容和独有词在 recall 正文、预览、`forget(about)`、`status`、访问记录中均未出现。
- `sensitive` 在未开启时从未出现。
- 5 种伪造的 `consent` 值都被拒绝；AI 无法降低敏感度；非法敏感度值回落为规则判定。
- 所有组合下输出都不超过预算。
- 每小时 30 次的 recall 限流在探测中真实触发。

**发现并修复的**：

| # | 严重度 | 复现 | 修复 |
|---|---|---|---|
| R1 | 高（忠实性） | "我以为跑步会有用，结果没用" → `exercise:+` | 期待句（以为 / 希望 / thought it would）不产生效果，看下一分句的结果 → `exercise:0` |
| R2 | 高（忠实性） | "我不确定是不是麻木" → `numb:low` | 不确定 / 疑问（是不是、会不会、maybe、am I、…吗？）在**记录**时不产生信号；**提问**时保留，"我是不是又麻木了？"仍会触发回忆 |
| R3 | 高（忠实性） | "他很焦虑，我陪他散步…" → 用户 `anxiety:high` | 以他人开头的分句不产生用户本人的状态 |
| R4 | 中（忠实性） | "I don't think I'm numb anymore" → `numb:high` | 否定前缀加 "don't think I'm"，后缀加 "anymore" |
| R5 | 中 | `recall(focus: "__proto__")` 走到原型链，报内部错误 | `Object.hasOwn` |
| R6 | 中 | 笔记里的 U+202E 等双向控制字符进入上下文，可在界面上倒序显示文字 | `safeQuote` 去除 U+202A–202E、U+2066–2069 |
| R7 | 低 | `initialize` 的 `params: null` → Internal error | `params` 非对象时按空对象处理 |
| R8 | 低 | "I went for a run" 未识别为运动；"身体没那么僵了"未识别为缓解；"谢谢"被存成事件 | 补词表与停用词 |

以上均有回归测试（`test/privacy.test.js`、`test/gate.test.js`）。

**残余**：换行被去掉后，笔记里伪造的标题（`ANCHOR: 'evil'`）只能出现在引号内的同一行，无法另起一行冒充分区，但模型仍可能读到它（T3）。"没有散步，因为下雨"仍会给事件打上 `walk` 标签（只影响搜索，不影响 HELPED）。"朋友说我最近很烦躁"被记为用户的状态，其实是他人的观察。

## 3. 仍未解决的问题

| # | 严重度 | 问题 | 为什么还没做 / 计划 |
|---|---|---|---|
| O1 | 高（产品价值） | **词典覆盖**：词典外的说法（"心里空落落的"、"脑子一片空白"、方言、隐喻）识别不到，检索就会漏。检索质量**从未在真实数据上测过** | 需要经知情同意、去标识化的真实说法集。计划：先建 200 条带标注的改写集，测"该出现的槽位出现了没有"；再评估可选的本地 embedding（只在设备上，删除同步） |
| O2 | 高 | **MCP 端的同意是软约束**：`consent: "user_asked"` 由 AI 填写，服务端无法验证 | 硬化需要宿主支持 elicitation（由宿主直接问用户）。先依靠宿主对非只读工具的确认弹窗、访问记录和可撤销 |
| O3 | 高（对这个人群） | **本机明文**：共用设备、控制型伴侣能直接读 `~/PersonalMemory` | 口令加密会带来"忘记口令就全丢"的风险，需要和用户、专业人员一起设计（P5） |
| O4 | 中 | **固定开销大于记忆本身**：工具定义约 600–800 token（真实值随宿主和分词器变化），而典型记忆上下文只有 50–150 token。"一次对话 100–500 token"只对记忆本身成立 | 可选：合并 `forget` 和 `memory_info`；依赖支持延迟加载工具的宿主；在 Skill 平台上只用"Skill + 胶囊" |
| O5 | 中 | **MCP 中的 Human Preview 是事后告知**：AI 读到时用户才看到预览，不是事先同意 | 真正的事先同意只存在于胶囊（复制前可见、可勾选）。以后在支持 elicitation 的客户端上改为先确认再返回 |
| O6 | 中 | 旧笔记不会随解析器升级重新结构化 | 数据已为此保留（`words`、`hints`、`parser`）；迁移时敏感度只升不降 |
| O7 | 中 | **胶囊的持久性和托管**：iOS Safari 可能清理本地存储；手机上打开本地 HTML 很难；大陆托管需要备案 | 维护者决定托管方式；页面已申请持久存储并提示导出 |
| O8 | 中 | token 估计是启发式的：部分分词器一个汉字会拆成多个 token，这时"保守估计"就不保守了 | 默认预算 300 离宿主上下文上限很远；上线前按目标宿主的分词器校准 |
| O9 | 低 | "他们说我很奇怪，我很难过"这类句子以他人开头，门控会漏掉 | 宿主 AI 仍可用 `focus` 显式调用 |
| O10 | 低 | 繁体中文不在词典内（如"焦慮"） | 加繁简映射（纯数据改动） |
| O11 | 低 | 危机词误报（"不想活在别人的期待里"） | 按设计宁可误报；只会多一行安全提示 |
| O12 | 低 | 时间窗口（14 天）、时期间隔（3 天）、回看范围（90 天）都是拍脑袋的常数 | 有真实使用数据后再调 |
| O13 | 低 | 两个 MCP 进程同时写，后写者胜 | 单用户、低频写入；需要时加锁文件 |
| O14 | 中 | **记忆文件模式违背"最少分享"**：整份文件交给 AI；而且规则（不诊断、不编造、`【新记忆】`格式）只能靠 AI 自觉遵守，各家模型遵守得如何**没有测过** | 维护者明确优先"发给 AI 就能用"。下一步：拿同一份文件在豆包、DeepSeek、Kimi、元宝、ChatGPT、Claude 上各跑一遍 Day 1 / Day 20，记录哪些规则被遵守 |
| O16 | 高（产品价值） | **锚点卡的效果完全取决于模型是否遵守卡上的规则**（先着陆、不追问、不诊断、不编造），各平台都**没有实测**；生成器能否在访谈中问出"具体"的内容也没有测过 | 下一步：用示例卡在 ChatGPT、Claude、豆包、DeepSeek 上各测一组固定场景（麻木、断片、情绪骤降、危机、无关问题），逐条记录遵守情况，再改卡片措辞 |
| O17 | 中 | 卡片越短越好放，但越短越难"精准细致"；1400 字是按 ChatGPT 免费版定的上限 | 付费版和 Claude 可以放长卡；以后可以让生成器按平台输出长短两个版本 |
| O15 | 低 | 用户手动维护文件，可能把 `【新记忆】` 行贴错位置或改坏格式 | 解析器只认"日期｜类型｜内容"行，贴在文件任何位置都能读；读不懂的行会被忽略，不会报错 |

## 4. 未核实的外部事实（上架前必须核实）

- Claude Desktop 扩展**精选目录**的提交流程。
- 消费版 **Kimi App** 能否上传第三方 Skill（已核实的只有 Kimi Code CLI 支持 `SKILL.md`）。
- **千问 App** 第三方 Skill 的入驻条件（个人或公益项目能否入驻），以及是否必须云端托管。
- 豆包、DeepSeek、元宝不能安装第三方 Skill：这一点来自需求描述，本次没有独立核实。
- 危机热线号码：Skill 里只列了 120 / 110、988、Samaritans 116 123，其余交给宿主模型按地区补充。

## 5. 刻意没做的事

- 没有服务器、账号、统计、遥测，也没有"让 AI 记住一切"的开关。
- 没有 AI 推断的存储路径。与其设计"推断如何升级为事实"，不如让推断根本不入库。
- 没有为"架构漂亮"引入数据库、向量库、框架或构建链。Core 零依赖，约 1.5k 行，一个下午就能读完。
